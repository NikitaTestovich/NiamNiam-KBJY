# Проверки, покрытие и выпуск Android

Файлы workflow подготовлены локально. До первой отправки версии 0.5 GitHub Actions не запускались; настройки защиты ветки, environment и signing secrets не считаются выполненными наличием YAML.

## Проверки изменений

`.github/workflows/android.yml` запускается для pull request, push, merge queue (`merge_group`) и вручную. Проверяются модульные тесты, Android lint, сборка debug APK и инструментальные тесты на Android API 35. Обе группы тестов формируют отчёты JaCoCo. Отчёты и тестовая APK сохраняются в артефактах на 14 дней.

Дополнительный gate `scripts/ci/verify_test_results.py` требует существующий читаемый JUnit XML, хотя бы один реально выполненный тест и отсутствие ошибок тестов/runner. Один лишь код выхода Gradle 0 недостаточен: установка на физическое устройство может быть запрещена, а тесты не выполнены. Отдельные unit-тесты проверяют классификацию пустого, пропущенного, ошибочного и корректного отчёта.

В настройках защиты основной ветки после первой публикации workflow нужно назначить обязательным статус **merge-check**, запретить обход проверок и включить актуальность ветки или merge queue. Сам workflow не настраивает защиту репозитория. Не следует автоматически сливать изменения только из-за наличия зелёного workflow: соответствие требованиям проверяется отдельно.

Локальные команды из `android/`:

```text
./gradlew :app:verifyUnitCoverageBaseline :app:lintDebug :app:assembleDebug
./gradlew :app:createDebugAndroidTestCoverageReport
```

HTML и XML: `app/build/reports/coverage/test/debug/` для unit и `app/build/reports/coverage/androidTest/debug/connected/` для Android. Точные файлы проверяются после запуска. Отчёты unit и Android охватывают разные сценарии; проценты нельзя складывать. Счётчик тестов не равен покрытию кода, а покрытая строка не доказывает правильность всех входных данных.

## Публикация обновления

`.github/workflows/release.yml` запускается вручную с номером версии, возрастающим Android `versionCode` и включённым `confirm_publication`. Сначала повторно выполняется весь workflow проверки. Только затем запускается job публикации через GitHub environment `release`.

Перед применением настроить environment `release`: разрешённая основная ветка, required reviewer и секреты `SIGNING_KEYSTORE_BASE64`, `SIGNING_STORE_PASSWORD`, `SIGNING_KEY_ALIAS`, `SIGNING_KEY_PASSWORD`. Секреты не записываются в проект. Используется постоянный ключ: смена сертификата нарушает обычное обновление уже установленного APK. Debug и release имеют разные подписи, поэтому debug APK не является проверкой реального release-обновления.

После успешных проверок workflow собирает release APK, выравнивает, подписывает, проверяет подпись, формирует SHA256SUMS и публикует стабильный GitHub Release основного публичного репозитория `NikitaTestovich/NiamNiam-KBJY`. Имя APK: `niamniam-kbjy-vc<versionCode>.apk`. Workflow проверяет, что code больше предыдущих стабильных release assets, и не перезаписывает существующую версию. В случае одновременных публикаций применяется последовательная очередь.

Перед созданием `SHA256SUMS` отдельный шаг проверяет фактический подписанный файл. `zipalign` проверяет выравнивание 16 КиБ, `apksigner` проверяет подпись, а `verify_release_apk.py` проверяет `com.niamniam.kbjy`, номер и имя версии, отсутствие режима отладки, целостность ZIP и отсутствие известных локальных артефактов, тестовых изображений и строк с секретами в DEX и assets. Шаг публикации передаёт GitHub только APK с ожидаемым именем и файл контрольной суммы. [Документация Android о выравнивании APK](https://developer.android.com/tools/zipalign) · [Документация Android о проверке подписи](https://developer.android.com/tools/apksigner)

25 ноября 2026 года локально выровнен и подписан одноразовым ключом APK 0.5 с `versionCode=1`. Все проверки готового файла и сверка SHA-256 прошли. Попытка проверить этот же файл как версию 0.6 завершилась отказом. Одноразовый ключ удалён. В GitHub Actions соответствующий workflow пока не запускался.

Для последующих выпусков CI выбирает APK с наибольшим `versionCode` среди стабильных релизов и сверяет единственный сертификат подписания со следующим APK. Отличающийся сертификат останавливает публикацию. Для первого релиза проверяется единственный сертификат нового APK. Локальная проверка подписанных APK 0.5 и 0.6 подтвердила совпадение сертификатов и отказ при использовании другого ключа для APK 0.6. [API загрузки APK из GitHub Releases](https://docs.github.com/en/rest/releases/assets#get-a-release-asset) · [Правила Android для обновления приложения](https://developer.android.com/google/play/app-updates)

Окончательная проверка выпуска включает действующий сертификат установленного приложения, digest опубликованного asset, совместимость версии и запуск без потери локальных данных. Эти проверки нельзя считать завершёнными до реального подписанного выпуска. Политика онлайн-обновления описана отдельно в `updates.md`.

### Проверка файлов перед первой публикацией
