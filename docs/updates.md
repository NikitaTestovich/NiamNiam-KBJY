# Обновление приложения

Обновление APK запускается пользователем; дневник, каталог, OCR и расчёты остаются доступны без интернета. Пользователь выбрал открыть основной репозиторий и использовать GitHub Releases `NikitaTestovich/NiamNiam-KBJY`. Репозиторий уже открыт, но релиз ещё не опубликован: приложение сообщает, что опубликованный релиз недоступен. В APK нет токена владельца репозитория.

Первый адаптер обновления повторяет подход Bumajnik-Android: проверка публичного GitHub Releases, выбор APK с более высоким versionCode, SHA-256, проверка имени пакета и сертификата подписания перед передачей системному установщику Android. Поддержка HTTPS-сервера возможна отдельным адаптером после выбора адреса и формата метаданных; существующие проверки APK должны сохраняться для обоих каналов.

Реальная доставка требует выпуска подписанного APK и успешного теста обновления старой установленной версии на новую с сохранением данных. До приёмки версии 0.5 ничего не публикуется. Для обновления нужен тот же package ID и подписывающий ключ; ключи хранятся отдельно от Git и APK. Установку подтверждает пользователь в системном интерфейсе Android. Имя release-артефакта: `niamniam-kbjy-vc<versionCode>.apk`; у GitHub asset должен быть digest `sha256:<64 hex>`.

Основной релиз поставляется одним APK для 32- и 64-битных ARM-устройств (`armeabi-v7a` и `arm64-v8a`). Для установки Android должен поддерживать хотя бы одну из этих архитектур. Тестовые debug-сборки также содержат библиотеки x86 и x86_64 для эмуляторов.

## Конфиденциальность и интернет

Разрешение INTERNET необходимо загрузчику обновлений. Оно не требует от пользователя подключаться к сети для работы дневника. На сервер обновлений передаются обычные сетевые сведения запроса (например IP-адрес); дневник, профиль, рецепты и фотографии не отправляются кодом обновления.

После включения INTERNET нельзя больше утверждать, что приложение технически лишено сетевого доступа. Google ML Kit обрабатывает изображения на устройстве, но его SDK может передавать диагностические сведения согласно [условиям Google](https://developers.google.com/ml-kit/terms). Для включения сетевых разрешений перед выпуском проверить фактическое поведение SDK и пользовательское описание. Ранее выполненная проверка манифеста без INTERNET относится к прежней сборке.

## Приёмка

- Нет канала: понятное сообщение, дневник работает.
- Нет сети/ошибка сервера: понятная ошибка, повторная попытка доступна.
- Нет новой версии: сообщение без предложения установки старой версии.
- Повреждённый APK, несовпадающий SHA-256, другой package ID, старый versionCode или другой сертификат: установка не предлагается, временный файл удаляется.
- Загрузка ограничена по объёму и времени; перенаправления допускаются только на разрешённые HTTPS-хосты адаптера.
- При выпуске проверяется реальное обновление ранее установленного подписанного APK на телефоне и сохранность базы, профиля и пользовательских файлов.

## Локальный тест замены APK

Тест `UpdatePersistenceTest` работает на существующем `NiamNiamTest` с отдельным пакетом `com.niamniam.kbjy.upgradetest`. Он включается отдельной командой AndroidJUnitRunner. Обычный прогон исключает команды заполнения тестовых данных.

1. Собрать две debug APK с `-PdeviceTestApplicationId=com.niamniam.kbjy.upgradetest` и последовательными `-PappVersionCode`. Вместе со старой сборкой сохранить её APK инструментальных тестов. Обе сборки должны использовать один ключ.
2. Установить старую сборку и APK тестов на чистый экземпляр этого пакета. Поместить новую APK через ADB в файл `cache/upgrade-candidate.apk` этого пакета. Вычислить SHA-256 новой APK на компьютере.
3. Запустить класс `com.niamniam.kbjy.UpdatePersistenceTest` с аргументами `upgradePhase=before`, `expectedCode` старой версии и `candidateSha`. Тест проверяет SHA-256, сертификат, имя пакета и номер версии и сохраняет образцы дневника, веса, профиля, продукта со штрихкодом и отчёта.
4. Выполнить `adb -s emulator-5554 install -r <новый.apk>` и снова запустить тест с `upgradePhase=after` и `expectedCode` новой версии. Проверка читает сохранённые записи и XLSX. Для контрольного отрицательного прогона режим `after` до заполнения пакета должен завершиться ошибкой из-за отсутствующих записей.

Локальная проверка использует тестовую подпись и установку через ADB. Для приёмки доставки из GitHub Releases нужен опубликованный APK с релизной подписью и проверка системного установщика.

24 ноября 2026 года на `NiamNiamTest` проверена замена APK с `versionCode=1` на `versionCode=2`. До установки подтверждены SHA-256 файла и совместимость сертификата и пакета. После установки совпали записи еды и напитка, сохранённый продукт со штрихкодом, замер веса, профиль и цель на указанную дату. Ранее сохранённый тестовый XLSX открылся и содержал обе записи. Отрицательный контроль на пустой установке завершился ошибкой на проверке дневника. Обе APK собраны из одного набора исходников, поэтому этот сценарий проверяет сохранность данных при замене приложения с текущей схемой базы. Миграции Room проверяются отдельно в `DiaryDatabaseTest`.

## Проверка системного установщика 25 ноября 2026 года

На том же `NiamNiamTest` штатный установщик обновил отдельную копию `com.niamniam.kbjy.upgradetest.installer` с `versionCode=1` до `2`. Тест подал локальный APK через тестовый транспорт, затем штатный код проверил SHA-256, подпись, пакет и номер версии. При первом прогоне установщик отказался читать URI, поскольку два провайдера были зарегистрированы с одним классом. После выделения класса `UpdateFileProvider` установщик открыл APK по URI обновлений. Обычный Android-тест проверяет, что оба URI читаются в одном процессе. [Документация AndroidX о FileProvider](https://developer.android.com/reference/androidx/core/content/FileProvider)

Установка подтверждена в системном диалоге. Повторная проверка нашла еду и воду в дневнике, продукт со штрихкодом, замер веса, профиль, цель и читаемый XLSX. Эти результаты относятся к локальным debug APK. Для проверки GitHub Releases нужен опубликованный релиз с рабочей подписью. [Как Android проверяет совместимость обновлений](https://developer.android.com/google/play/app-updates)

Для повтора соберите обе версии с идентификатором `com.niamniam.kbjy.upgradetest.installer` и выполните шаги 1–3 локальной проверки выше на отдельном экземпляре пакета. Разрешите этому экземпляру устанавливать APK в настройках эмулятора. Вызовите `UpdatePersistenceTest#openSystemInstallerForTheVerifiedCandidate` с `upgradePhase=installer`, номером установленной версии в `expectedCode` и SHA-256 новой в `candidateSha`. Подтвердите установку в штатном диалоге, запустите проверку с `upgradePhase=after` и верните настройку установки APK в исходное состояние.
