# Стратегия собственного офлайн-каталога

Дата исследования: 21 ноября 2026. Назначение приложения — личное использование, семья и знакомые, без планов коммерциализации. Передача APK другим людям всё же является распространением копии; отсутствие оплаты само по себе не отменяет условий лицензий.

## Решение для подготовки

Собрать общий локальный поиск по раздельно хранимым наборам с проверенным происхождением: USDA FNDDS (CC0), отдельная выборка Open Food Facts (ODbL/DbCL), в дальнейшем — подходящие записи Fineli (CC BY 4.0) и других проверенных источников. Пользовательские продукты, рецепты, профиль и дневник хранятся отдельно от распространяемых стартовых данных. Приложение работает без интернета; сбор и проверка данных выполняются на этапе подготовки каталога.

Раздельное хранение и общий поиск — практические меры для сохранения происхождения, но сами по себе не доказывают, что результат является коллективной, а не производной базой в смысле лицензии ODbL. Перед распространением проверить применимость условий к конкретному набору и преобразованиям. [ODbL 1.0, определения и раздел 4](https://opendatacommons.org/licenses/odbl/1-0/). В [руководстве OFF по локальному кешированию](https://openfoodfacts.github.io/documentation/docs/Product-Opener/api/tutorials/creating-a-local-cache-of-open-food-facts-data/) содержится указание не смешивать данные OFF с внешними продуктовыми данными и передавать изменения обратно; его применимость к выбранному способу поставки нужно отдельно установить. Личные пользовательские данные автоматически никуда не передаются.

## Правила качества данных

1. Для каждой записи хранить исходный идентификатор, исходное название, версию/дату источника, URL источника и лицензию; переводы и синонимы отмечать отдельно как проверенные или ожидающие проверки.
2. Для готового продукта показывать ккал и БЖУ на подтверждённые 100 г либо 100 мл. Отсутствующее значение не заменять нулём. Данные на порцию без её массы или объёма автоматически не переводить в значения на 100 единиц.
3. Не считать блюда с разными ингредиентами и способом приготовления взаимозаменяемыми. Пользователь должен видеть, что данные для типового блюда ориентировочные; для собственного блюда сохраняются ингредиенты и итоговая масса.
4. Коды нормализовать и проверять; совпадающие записи не объединять автоматически только по названию. При конкурирующих значениях сохранять источник каждого варианта и не смешивать отдельные показатели разных продуктов.
5. При обновлении поставляемого каталога не перезаписывать личные продукты, рецепты, дневник и исторические значения. Дневник хранит фактические показатели на момент внесения.
6. Контрольный набор из 50 продуктов и 100 блюд проверять на реальном поиске приложения с ручной оценкой соответствия. Цель — минимум 45 продуктов и 90 блюд. Счётчик записей и текстовые совпадения не подтверждают прохождение.

## Следующие шаги

- Исследовать скачиваемый Fineli: формат, ккал/БЖУ, единицы, переводы, дубликаты и покрытие контрольных запросов до добавления в APK. По [официальной инструкции](https://fineli.fi/fineli/content/file/8) энергия предоставляется в кДж и пересчитывается в ккал делением на 4,184; значения БЖУ указаны на 100 г съедобной части с оговорёнными исключениями. Документ предупреждает, что ноль иногда может быть связан со старыми версиями данных: нулевые значения требуют дополнительной проверки, а не автоматического признания точными.
- Возобновить сверку кандидатов OFF с первоисточником при доступности сервиса с соблюдением ограничений. На предыдущем прогоне API возвращал 503; промежуточные результаты сохранены.
- Подготовить доступные без интернета сведения об источниках и лицензиях и проверить состав release APK; см. [аудит](THIRD-PARTY-AUDIT.md).
- Обеспечить отдельный процесс подготовки и приёмки своих рецептур: фиксировать исходные ингредиенты, их массы и массу готового блюда, вычислять КБЖУ и отмечать их как ориентировочные. Не придумывать значения или вес готовой порции.
- Выполнить ревизию лицензий, происхождения данных и тестов до передачи приложения другим людям. Ничего не отправлять на GitHub до готовности версии 0.5 и проверки на чувствительные данные.
